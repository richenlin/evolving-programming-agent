# TDD 核心规则

> 供 @coder 在 full-mode / simple-mode 中引用。借鉴 Superpowers test-driven-development skill，保留 EPA 轻量集成。

## 铁律

```
没有先失败的测试，就不写生产代码。
```

先写了实现再补测？**删掉实现，从测试重来**（探索性 spike 除外，spike 代码不得直接提交）。

## RED → GREEN → REFACTOR

| 阶段 | 动作 | 必须验证 |
|------|------|----------|
| **RED** | 写一个最小失败测试（一个行为、清晰命名） | 运行测试，确认**因功能缺失而失败**（非 typo/环境错误） |
| **GREEN** | 写最少代码让测试通过 | 运行测试，确认通过且其他测试仍绿 |
| **REFACTOR** | 去重、改名、提取 helper | 测试保持全绿，不新增行为 |

## 模式差异

| 场景 | TDD 要求 |
|------|----------|
| **full-mode 新功能** | 每个新函数/行为严格 RED-GREEN-REFACTOR |
| **simple-mode bug 修复** | 先写**复现 bug 的失败测试** → 修复 → 验证通过（防回归） |
| **纯配置/文档** | 可跳过，在 progress.txt 注明原因 |

## 完成前自检

- [ ] 每个新行为有对应测试
- [ ] 见过测试先失败（bug 修复：见过复现测试失败）
- [ ] 失败原因是「功能缺失」而非测试写错
- [ ] 实现是满足测试的最小代码（YAGNI）
- [ ] 全部测试通过，输出无 error/warning

## 反合理化（出现即 STOP）

| 借口 | 现实 |
|------|------|
| "太简单不用测" | 简单代码也会坏；写测试 30 秒 |
| "写完再补测" | 立即通过的测试证明不了什么 |
| "手动测过了" | 无记录、不可复跑、易漏边界 |
| "删了 X 小时太浪费" | 沉没成本；无测试的代码是技术债 |
| "留着当参考，先写测试" | 你会改它——那就是测后写 |
| "就这一次" | 例外会变成习惯 |

## 测试质量

| 好 | 坏 |
|----|-----|
| 测真实行为、清晰命名 | `test1`、测 mock 而非代码 |
| 一个测试一个行为 | 名字里多个 "and" |
| 真实代码（mock 仅必要时） | 过度 mock 掩盖设计问题 |
